# 硬件板卡检查清单

## 当前状态诊断

- ❌ UDP通信：无响应（端口8080未监听）

## 问题定位

**板卡硬件正常，但UDP应用程序未运行**

## 检查步骤

### 1. 物理检查

- [ ] 检查板卡电源指示灯是否亮起
- [ ] 检查板卡网口指示灯是否闪烁
- [ ] 检查是否有显示屏/LED状态显示
- [ ] 观察板卡是否有蜂鸣器报警

### 2. 程序状态检查

- [ ] 板卡是否需要手动启动UDP服务？
- [ ] 是否有串口命令可以启动UDP模式？
- [ ] 是否需要通过Web界面配置？
- [ ] 是否需要按下物理按钮切换模式？

### 3. 固件检查

- [ ] 确认板卡固件版本（查看技术文档）
- [ ] 检查固件是否支持UDP通信
- [ ] 确认UDP端口号配置（默认8080？）
- [ ] 检查是否需要特殊的握手协议

### 4. 复位尝试

- [ ] 方法1：板卡断电重启（关机→等待10秒→开机）
- [ ] 方法2：按下复位按钮（如果有）
- [ ] 方法3：通过串口发送复位命令
- [ ] 方法4：通过其他接口（如USB/JTAG）重新加载程序

### 5. 协议验证

- [ ] 查阅板卡技术手册，确认通信协议格式
- [ ] 确认Header是否为0x55AAAA55（C#代码中的定义）
- [ ] 确认包长度是否为28字节
- [ ] 确认是否需要先发送配置包再发送Ping

## 常见原因排查

### 情况A：板卡需要初始化

某些FPGA板卡启动后处于待机状态，需要：

1. 通过串口发送 `start` 或 `init` 命令
2. 通过Web界面点击"启动服务"
3. 发送特定的配置包激活UDP模式

**操作**：查阅板卡说明书的"启动流程"章节

### 情况B：板卡在等待特定格式的初始化包

某些设备需要先接收配置包：

```
步骤1: 发送 Config Packet (CmdID=2)
步骤2: 等待 ACK
步骤3: 发送 Ping Packet (CmdID=0)
```

**操作**：修改C#代码，在Ping前先发送Config包

### 情况C：UDP端口号不是8080

板卡默认端口可能是其他值：

- 常见端口：8080, 8000, 9000, 10000, 5000

**操作**：用Wireshark抓包，查看板卡是否在其他端口响应

### 情况D：板卡固件版本过旧

旧版本固件可能不支持UDP通信

**操作**：联系厂商获取最新固件并升级

## Wireshark抓包分析

### 安装Wireshark

```powershell
# 下载地址
https://www.wireshark.org/download.html
```

### 抓包步骤

1. 打开Wireshark
2. 选择网卡（显示192.168.2.100的那个）
3. 过滤器输入：`ip.addr == 192.168.2.88`
4. 点击"开始捕获"
5. 运行Python脚本发送数据
6. 观察板卡是否有任何UDP响应

### 分析要点

- **只有ICMP响应**：说明板卡UDP服务未运行
- **有ARP请求但无UDP**：说明网络配置问题
- **有UDP响应但端口不同**：说明端口配置错误
